The OpenIncent Method

How to take commission from a messy spreadsheet to paid, reconciled, and explainable — the data it needs, the controls it must pass, and the eight steps that get there — mapped on one page.

1Method & engine

The method is the product — a repeatable way of working that ends in payouts you can prove. The engine is free software that runs it. You can follow the method by hand; the engine just makes it cheap and fast.

The method — defines

The data it needs, a named control library, a conformance ladder, and eight repeatable steps. Versioned independently. This is the scarce, defensible asset.

→

The engine — runs it

icm validate · lint · check-plan · reconcile. Free and open (AGPL), cloneable — and that's the point.

2Data model — relationships

Three inputs feed a run: the plan, the payees, and the transactions. Owned value objects (draws, tiers, ramps, assertions) attach to their parent; side-inputs and the commission output reference payees.

3Data model — entities

Key fields per entity. PK primary key · FK foreign key · REQ required.

Plan config

Plan YAML

  • PKplan_id
  • REQname, period_type, currency
  • rules[] one or more
  • payout_cap, draw, pro_rating
  • rounding, ote, assertions[]

Rule discriminated

  • REQtype, id, rate/tiers
  • filter boolean expr
  • cap, min_attainment_pct
  • quota_category
  • base amount | margin

Tier

  • REQthreshold_pct > 0
  • REQrate ≥ 0
  • ascending by threshold

PlanAssertion

  • REQname, quota, deals[]
  • REQexpect_total
  • base, period, tolerance

Draw

  • REQamount ≥ 0
  • recoverable bool
  • plan- or payee-level

RoundingPolicy

  • mode half-up/even/floor/ceil/none
  • places 0–6
  • display boundary only

Roster

Payee CSV / XLSX

  • PKid
  • REQname, quota
  • FKplan_id → Plan
  • effective_from / _to
  • quotas{} category_quotas{}
  • FKmanager_id → Payee
  • manager_override, team_id, email

RampSchedule

  • REQmonths > 0
  • REQschedule[] multipliers
  • length must equal months

Deal data

Transaction CSV/XLSX/Parquet

  • PKid
  • FKpayee_id → Payee
  • REQperiod or close_date
  • amount may be negative
  • product, deal_id
  • bill_rate / pay_rate / units / margin
  • credits, quota_amount
  • …metadata passthrough

Credit

  • FKpayee_id → Payee
  • REQsplit_pct in (0,1]
  • kind split | overlay
  • splits sum to 1.0

Side-inputs & output

ManualAdjustment CSV

  • FKpayee_id, period
  • REQamount, reason
  • applied last; ignores caps/draws

MBO / bonus CSV

  • FKpayee_id, period

Commission output

  • FKtransaction_id, payee_id

5Conformance ladder

Each level is the acceptance gate for the next. A managed engagement does not go live until L3.

L0

Parses

All three inputs load against the data spec.

icm calculate runs without a load error
L1

Validated

No error-severity findings; warnings reviewed and accepted.

icm validate clean
L2

Plan-verified

Plan structurally clean; every assertion passes.

icm lint + icm check-plan
L3

Reconciled

Run matches the last real pay cycle, line for line.

icm reconcile clean

6The method — eight steps

Messy spreadsheet → conformant, reconciled, paid. The same eight steps whether you run the engine yourself or have someone run it for you. Each step earns a rung on the ladder above.

  1. Intake

    Collect the plan (any form), last period's deal extract, the payee roster, and what was actually paid (the reconciliation target).

  2. → L0

    Map to the spec

    Map the client's columns onto canonical fields. icm map previews the inferred mapping; review and lock it.

  3. → L1

    Validate the data

    Run icm validate. Resolve every error; review each warning with the client and record whether it's a defect or a conscious exception.

  4. → L2

    Encode the plan as code

    Translate the plan into the spec. Where prose is ambiguous, get a written answer — never guess. Add assertions; run icm lint + check-plan until clean.

  5. Calculate

    Run icm calculate. Produce statements and the audit ledger. Spot-check payouts with icm trace — every number explains itself.

  6. → L3

    Reconcile

    Run icm reconcile against what was actually paid. Investigate every discrepancy. Iterate steps 4–6 until clean or explained. Acceptance.

  7. Lock & hand over

    Lock the period (pins the official run, generates the payout register). Distribute statements (safe by default). The client owns the plan, config, and data — no lock-in.

  8. Run the cadence

    Each period repeats steps 2–7 on new data against the fixed plan. Late deals flow through as period-locked true-ups. Setup-only clients run this loop themselves.

Throughout: non-identifying payee IDs where possible, confidentiality of all client data, deletion of working copies within the contracted retention window — flowing down unchanged to any partner or contractor.
